# 项目引言：MovieLens 1M 数据分析 Agent 系统

## 1. 整个系统的简要需求

本项目以 MovieLens 1M 数据集为基础，分三次迭代建设一个由 Agent 驱动的大数据处理与分析系统。用户通过简易前端输入自然语言请求，Agent 根据任务类型调用 Hadoop、机器学习、图分析和知识图谱工具，返回实际执行状态、分析结果及其依据。

系统应满足以下总体要求：

- 三次迭代逐步衔接，后一轮复用前一轮已经登记的数据、模型和分析结果。
- 数据、清洗规则、模型、知识图谱和评价结果均应保留版本信息，避免混用不同版本的产物。
- 第一轮统一确定时间边界 `T1/T2`。`T1` 为训练期截止时间，`T2` 为验证期截止时间，测试数据位于 `T2` 之后。
- Agent 应将实际处理能力封装为可调用工具，并根据用户请求完成任务。没有可用数据、模型或结果时，应明确返回失败原因或未完成状态。
- 系统不得使用占位数据、示例结果或主观推测代替实际运行结果，也不得使用验证期或测试期信息构造训练输入。
- 前端应支持自然语言输入、任务状态展示、结果查看、证据说明和异常提示，不要求复杂的页面设计。

## 2. 每次迭代的简要需求

### 2.1 迭代一：Hadoop 数据清洗与质量评估

迭代一建设 MovieLens 数据治理 Agent。Agent 调用 Hadoop 检查和清洗原始数据，并分别对清洗前后的数据进行 Accurate、Complete、Unique、Up-to-date、Consistent 五个维度的质量评分。

本轮需要输出清洗后的数据、数据版本、清洗规则版本、任务标识、`T1/T2` 和评估报告。系统还应展示清洗前后的评分变化、数据量变化、异常记录处置方式、仍未解决的问题及评价局限。

### 2.2 迭代二：分类、聚类与降维分析

迭代二使用第一轮输出的清洗数据和时间边界，增加分类、聚类和降维三类分析能力：

1. 分类任务预测用户对电影的评分是否不低于 4 分。
2. 聚类任务根据用户历史观影偏好形成用户群体。
3. 降维任务压缩用户偏好画像，并比较降维前后的聚类结果、信息保留情况和资源开销。

每类任务均须从相应 PPT 介绍的算法中任选两种实现，并将每种算法封装为可供 Agent 独立调用的工具。系统应保留分类模型、用户画像、用户群体、降维模型及坐标、算法参数、评价指标和版本信息，供第三轮使用。

### 2.3 迭代三：知识图谱及其上层任务

迭代三首先使用前两轮的成果构建电影领域知识图谱。图谱至少包含用户、电影和类型等实体，以及用户评分电影、电影所属类型等关系；年龄段、性别、职业和邮编可以作为用户属性或实体保存。每个实体和关系都应保留数据来源、训练截止时间和版本信息。

知识图谱完成构建与校验后，系统在同一图谱版本或其图投影上完成以下任务：

1. 推荐任务根据用户历史行为和电影关系生成推荐结果。
2. 图挖掘任务发现电影社区及其结构特征。
3. 链接分析任务分析电影节点的重要性或关联程度，并生成排序结果。

每个任务均须从相应 PPT 介绍的算法中任选两种实现，并封装为独立的 Agent 工具。知识图谱未完成、校验失败或版本不一致时，三个任务不得运行。

## 3. MovieLens 1M 数据集简介

MovieLens 1M，简称 `ml-1m`，由明尼苏达大学 GroupLens Research 发布，是一个稳定的电影推荐基准数据集。该数据集包含 2000 年加入 MovieLens 的用户所产生的电影评分，并于 2003 年 2 月发布。

| 项目 | 数据规模或范围 |
| --- | --- |
| 用户数量 | 6,040 位匿名用户 |
| 电影记录数量 | 3,883 条，约 3,900 部电影 |
| 评分数量 | 1,000,209 条 |
| 用户范围 | 2000 年加入 MovieLens 的用户 |
| 发布时间 | 2003 年 2 月 |
| 评分范围 | 1 至 5，仅包含整数评分 |

数据集由三个 `.dat` 文件组成，文件不包含表头，字段之间使用 `::` 分隔，文本采用 ISO-8859-1 编码：

| 文件 | 主要字段 | 内容 |
| --- | --- | --- |
| `ratings.dat` | `UserID::MovieID::Rating::Timestamp` | 用户对电影的整数评分及评分时间 |
| `users.dat` | `UserID::Gender::Age::Occupation::Zip-code` | 用户自愿填写的性别、年龄段、职业和邮编信息 |
| `movies.dat` | `MovieID::Title::Genres` | 电影标题和类型信息 |

数据集中的用户标识已经匿名化，所有入选用户至少评价过 20 部电影。`users.dat` 中的人口属性由用户自愿填写，GroupLens 未核验其准确性；年龄和职业使用类别编码，邮编应按字符串处理，以免丢失前导零。电影类型使用竖线分隔，一部电影可以属于多个类型。MovieID 的最大值不代表实际电影数量，因为编号并不连续。

## 4. 每次提交内容

每次迭代结束后，小组应提交与本轮需求对应的完整成果。提交内容如下：

| 提交内容 | 要求 |
| --- | --- |
| 源码 | 必须提交。包括本轮实现代码、Agent 工具、前端代码、配置文件及必要的运行脚本。 |
| 相关文档 | 必须提交。包括系统说明、运行方法、工具接口、数据与模型版本、实验配置、评价结果和已知限制。 |
| PPT | 可选。可用于辅助现场汇报或说明系统设计与结果。 |
| 演示视频 | 可选。可用于替代现场系统操作展示。 |
| 其他汇报文档 | 可选。可以提交报告、海报或其他有助于说明本轮成果的材料。 |

提交的源码和文档应与汇报时展示的系统版本一致，并能够说明本轮完成的功能、实际运行结果及尚未解决的问题。

## 5. 汇报要求

- 每次汇报应展示本轮完成的系统及其实际运行结果。
- 可以使用预先录制的视频替代现场系统操作展示。
- 可以使用 PPT 辅助说明系统设计、算法和实验结果。
- 不强制要求制作演示视频或 PPT，小组可根据汇报需要自行选择。
- 每次汇报时间控制在 10 分钟左右，应优先展示核心功能、真实结果、评价结论和主要限制。
- 若系统运行失败或部分功能尚未完成，应如实说明当前状态、失败环节和原因，不得使用模拟结果替代。
