# 迭代一：Agent 驱动的 Hadoop 数据清洗与五维质量评估

## 1. 目标与最终效果

本轮建设 **MovieLens 数据治理 Agent 系统**。用户在简易前端输入自然语言请求后，Agent 自动检查数据，调用 Hadoop 对原始数据评分、执行清洗并对清洗结果再次评分，最终展示清洗前后的对照结果、处理原因和评估报告。

示例提示：

> 请使用默认规则清洗 MovieLens 1M，评估清洗前后的 Accurate、Complete、Unique、Up-to-date、Consistent 五个维度，并说明处理了哪些问题、还有哪些问题无法解决。

环境与数据源由学生事先配置。正常演示中，用户提交一次请求即可，无需手动运行 Hadoop 命令、上传中间文件、逐阶段点击按钮或计算指标。

本轮应输出清洗后的数据、数据版本、清洗规则版本、任务标识和评估报告，并确定供后续迭代统一使用的时间边界 `T1/T2`。其中，`T1` 为训练期截止时间，`T2` 为验证期截止时间；测试数据位于 `T2` 之后。后续迭代不得混用不同数据版本或时间范围的产物。

## 2. 数据清洗需关注的潜在问题

针对 `ml-1m`，学生可从以下方面识别可能存在的数据质量问题。以下内容是检查方向，不代表原始数据一定存在这些错误；具体问题应以实际分析结果为依据，清洗方案由学生自主设计。

### 2.1 通用数据问题

- **文件与解析问题：** ISO-8859-1 编码处理错误、字段数量不符、`::` 分隔符使用异常，或读取时错误地将首行作为表头，导致记录无法正确解析。
- **缺失问题：** 关键字段为空、仅包含空白，或缺失信息使用不同标记表示。
- **类型与格式问题：** 数值字段出现非数值内容，标识符格式异常，时间单位或日期表示不一致。
- **重复与冲突问题：** 同一记录重复出现，或同一标识对应相互矛盾的信息。
- **跨表关联问题：** 评分记录引用的用户或电影在对应信息表中不存在，或同一标识在不同文件中的含义不一致。

### 2.2 ratings.dat：评分数据

- UserID、MovieID、Rating 或 Timestamp 缺失或格式异常。
- 评分超出 1—5 的范围，或评分不是整数。
- 时间戳单位混淆、无法解释，或超出数据集说明的历史覆盖范围。
- 评分事件重复出现，或同一用户对同一电影在同一时间出现不同评分。
- 用户评分行为分布异常，例如评分数量明显偏高或评分高度集中；这些现象是否属于质量问题，需要结合数据背景判断。

### 2.3 movies.dat：电影信息

- MovieID 或电影标题缺失，标题存在多余空白、乱码等问题。
- 同一 MovieID 对应不同标题或类型信息。
- 类型信息缺失、重复、拼写不一致，或出现无法识别的类型名称。
- 标题中的年份缺失、格式异常或含义不明确。
- 不同电影存在同名情况，仅凭标题可能无法确定是否为同一电影。

### 2.4 users.dat：用户信息

- UserID、Gender、Age、Occupation 或 Zip-code 缺失或格式异常。
- Gender、Age 和 Occupation 出现数据说明之外的类别编码。
- 邮编读取为数值后丢失前导零，或出现无法解释的格式差异。
- 同一 UserID 对应多组相互冲突的用户属性。
- 用户属性由用户自愿填写且未经核验，格式正确不代表内容真实准确。

识别问题时，应区分真正的数据错误、信息不足和正常的业务现象。例如，不同时间的评分事件、用户属性分布不均以及数据年代较早，并不必然属于错误。

## 3. 清洗前后五维评分规范

系统需要从以下五个维度对清洗前后的数据集进行打分和比较。本节只明确各维度的含义，具体评价指标、打分方法、分值范围、权重及是否设置综合分，由学生结合 MovieLens 数据特点和应用场景自主设计。

| 维度 | 含义 |
| --- | --- |
| Accurate（准确性） | 数据的值应当真实反映现实世界的情况，避免错误或失真的信息。 |
| Complete（完整性） | 衡量业务所必需的数据是否完整，例如不能缺失的字段是否存在空值。 |
| Unique（唯一性） | 数据集中的每条业务记录应具有唯一性，避免重复记录和不必要的数据冗余。 |
| Up-to-date（时效性） | 数据应足够新，能够反映所关注对象的当前状态。 |
| Consistent（一致性） | 数据元素的类型、格式和含义应一致、清晰，不同记录及数据表之间不应相互矛盾，例如日期格式和单位是否统一。 |

学生需自行提出评分方案，说明设计依据，并通过 Hadoop 实现。可以结合字段、记录、数据表或整个数据集开展评价，具体组织方式不作统一规定。

方案应说明各维度如何衡量、哪些情况无法验证，以及评分结果能够支持什么结论。例如，格式正确是否足以证明真实性，历史数据应选择什么时间参照，均由学生讨论并说明理由。

清洗前后必须使用同一套评价口径，使结果可比较。前端展示五维得分及变化，Agent 根据实际结果解释改善、未解决的问题及数据删除或隔离带来的影响。不要求所有维度的分数都提高，也不预设必须达到的分数。

## 4. Hadoop 作为 Agent 的清洗与评分工具

系统应将 Hadoop 的数据清洗与质量评分能力封装为 Agent 可调用的工具。用户输入提示后，由 Agent 调用工具，使用 Hadoop 完成数据集清洗，以及清洗前后的五维质量评分。

Hadoop 负责实际的数据处理和评分计算，并将执行状态与结果返回给 Agent；Agent 负责组织任务、解释结果，并通过前端向用户展示。

Hadoop 的部署方式、工具接口、任务组织和具体实现由学生自主设计，只需确保清洗与评分实际通过 Hadoop 执行，并接入 Agent 的自动流程。

- **Agent 输入：** 用户的自然语言清洗与评估需求、原始数据版本，以及可选的清洗规则和评分配置。未指定配置时，Agent 使用已登记的默认方案。
- **Agent 输出：** 返回任务状态、清洗前后的五维评分、数据量变化、异常处置结果、清洗后数据版本、规则版本、`T1/T2` 和评估报告。执行失败或结果尚未生成时，应返回明确的状态说明，不得生成占位结果。

## 5. Agent 系统功能需求

用户通过自然语言向 Agent 提出数据清洗与评估需求。系统应理解用户目标，调用 Hadoop 工具自动完成清洗前评分、数据清洗、清洗后评分和结果对比，无需用户手动执行中间步骤。

系统应满足以下要求：

- **自动完成任务：** 一次提示即可发起完整的清洗与评估任务，返回实际执行结果。
- **说明执行状态：** 用户能够了解任务是否正在执行、已经完成或执行失败；发生异常时，说明失败环节和原因。
- **解释评估结果：** 说明五个维度的前后变化、清洗解决的问题，以及仍存在的问题和评价局限。
- **说明数据处置：** 区分修复、去重和隔离，解释数据量变化，避免将删除或隔离记录直接表述为问题已修复。
- **支持结果追问：** 用户可以继续询问分数变化、异常记录或清洗依据，Agent 的回答应有实际数据和评估结果支持。
- **保证结果可信：** 不编造分数或处理结果，不为提高分数擅自改变规则；任务执行完成不代表所有质量问题都已解决。

系统的具体实现方式由学生自主设计。

## 6. 前端展示需求

系统应提供简易前端页面，使用户能够输入自然语言请求、了解执行情况并查看清洗与评估结果。

页面应满足以下需求：

| 功能 | 需求说明 |
| --- | --- |
| 问题输入 | 用户能够输入自然语言需求并发起任务。 |
| 执行情况 | 展示任务状态和当前进展，失败时给出清晰提示。 |
| 五维评分对比 | 展示 Accurate、Complete、Unique、Up-to-date、Consistent 的清洗前后得分及变化；是否提供综合分由学生决定。 |
| 评分依据 | 说明学生设计的评价方法、适用范围和局限；未完成、无法评价和未验证的情况应清楚标注。 |
| 清洗结果 | 展示数据量变化、修复、去重和隔离情况，以及有代表性的问题记录和处理原因。 |
| Agent 解释与追问 | 展示 Agent 对结果的说明，并允许用户围绕本次任务继续提问。 |
| 结果获取 | 用户能够查看清洗后的数据样例，并获取评估报告。 |

页面应清晰易懂，展示内容与实际执行结果一致。页面布局、展示形式及技术选型由学生自主决定，不要求复杂的界面设计。
